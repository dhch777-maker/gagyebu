# 분트 인건비 엑셀 — 기간별 급여유형 지원

## 배경

기존 `분트_인건비관리_v2.xlsx`(2026-04-17 설계)의 **직원 마스터**는 한 직원당 한 행으로, 급여유형(월급/시급)을 하나만 지정할 수 있다. 그러나 원본 `분트 재무제표(25.12월).xlsb`의 지급 이력을 보면, 고경민은 시점에 따라 월급제와 시급제를 오갔다:

- 2025-01 ~ 2025-02: 월급 1,200,000원
- 2025-03 ~ 2025-09: 시급 12,000원 (일급여가 근무기록에 누적됨)
- 2025-10 ~ : 월급 1,300,000원

현재 구조는 현재 상태(월급 1,300,000) 하나만 반영하므로 급여 요약 탭에서 과거 월을 선택해도 1,300,000원 월급으로 잘못 계산된다. 이를 **기간별 급여 이력**으로 저장하도록 개선한다.

## 설계

### 직원 마스터 — 한 직원 여러 행 허용

컬럼 구조는 그대로 유지하되 F/G 컬럼의 의미를 확장한다.

| 열 | 헤더 | 유형 | 변경 |
|----|------|------|------|
| A | 이름 | 텍스트 | 중복 허용 |
| B | 급여유형 | 드롭다운: 월급/시급 | — |
| C | 금액 | 숫자 | 해당 구간 금액 |
| D | 입금계좌 | 텍스트 | — |
| E | 재직상태 | 드롭다운: 재직/퇴직 | — |
| F | **적용시작월** | YYYYMM | (기존 "입사월" → "적용시작월") |
| G | **적용종료월** | YYYYMM | (기존 "퇴사월" → "적용종료월", 현재까지면 공란) |
| H | 비고 | 텍스트 | — |

헤더 텍스트를 "적용시작월" / "적용종료월"로 변경한다.

**불변 조건**: 같은 이름의 여러 행이 **겹치는 기간을 가지지 않는다**. 각 시점에 활성 행은 최대 1개.

**초기 마이그레이션 데이터 (7행)**

```
고경민 | 월급 | 1,200,000 | 국민은행 82240104164295  | 재직 | 202501 | 202502 |
고경민 | 시급 |    12,000 | 국민은행 82240104164295  | 재직 | 202503 | 202509 |
고경민 | 월급 | 1,300,000 | 국민은행 82240104164295  | 재직 | 202510 |        |
장예원 | 시급 |    12,000 | 카카오뱅크 3333-07-7072641 | 퇴직 | 202502 | 202507 |
유은비 | 시급 |    12,000 | 우리 1002-533-898534      | 퇴직 | 202502 | 202503 |
전민아 | 시급 |    12,000 | 하나은행 558-910330-30707  | 재직 | 202503 |        |
김채현 | 시급 |    12,000 | 우리은행 1002-351-542250   | 퇴직 | 202507 | 202510 |
이진화 | 시급 |    12,000 | 우리은행 1002-166-678383   | 재직 | 202511 |        |
```

총 8행(고경민 3행 + 나머지 5명 1행씩).

**재직상태(E열) 의미**: 기존 구조에서는 필터링용 플래그였으나, 신규 구조에서는 **활성 구간 판별에 사용하지 않는다** (F/G만 사용). 각 행의 재직상태는 "**해당 사람의 현재 고용 상태**"를 표시하는 정보 컬럼으로 남긴다. 고경민 3행 모두 `재직`, 유은비·장예원·김채현은 모두 `퇴직`으로 표시.

### 근무 기록 — 수식만 수정

컬럼 구조와 원본 일급여 보존 로직은 변경하지 않는다. 단, **G열(급여유형) 수식**을 기간 기반 조회로 바꾼다.

기존:
```
=IF(B{r}<>"", VLOOKUP(B{r}, '직원 마스터'!A:B, 2, FALSE), "")
```

신규:
```
=IF(B{r}<>"",
  INDEX('직원 마스터'!B:B,
    MATCH(1,
      ('직원 마스터'!A$2:A$30=B{r}) *
      ('직원 마스터'!F$2:F$30 <= TEXT(A{r},"YYYYMM")*1) *
      (('직원 마스터'!G$2:G$30="") + ('직원 마스터'!G$2:G$30 >= TEXT(A{r},"YYYYMM")*1) > 0),
    0)
  ),
  "")
```

(배열 수식으로 Ctrl+Shift+Enter 필요 — openpyxl에서 `array_formula=True`로 설정)

신규 입력행의 자동 일급여 계산 수식(F열)도 같은 방식으로 해당 시점의 시급을 조회하도록 수정한다.

### 급여 요약 — 활성 구간 필터링으로 재구성

현 구조: 6개 직원 고정 순서로 4행~9행에 배치, 각 행이 마스터의 한 행을 참조.

신규 구조: **마스터의 모든 행(최대 20행)을 순회하며 활성 구간만 남겨 표시**.

- 헤더는 동일
- 직원별 행: 4행 ~ 23행 (최대 20행)
- 각 행 `r`은 마스터 행 `mr = r - 2`를 참조
- 활성 조건:
  ```
  AND('직원 마스터'!F{mr}<>"",
      '직원 마스터'!F{mr} <= $B$1,
      OR('직원 마스터'!G{mr}="", '직원 마스터'!G{mr} >= $B$1))
  ```
  (기존 로직과 동일 — F/G 의미 확장만으로 자연스럽게 동작)
- 이름 / 급여유형 / 금액(월급)은 **마스터의 해당 행 값을 그대로 참조**. 고경민의 경우 선택월에 매칭된 구간 행이 표시됨
- 총 근무시간 / 일급여 합산: 선택월의 근무기록 일급여 합계
- 총 급여(세전):
  - 시급제 구간: 근무기록 일급여 합계
  - 월급제 구간: 마스터의 해당 행 C열 값(고정 월급액)

**빈 행 처리**: 활성 아닌 마스터 행은 이름 셀이 공란이 되고, 나머지 계산열도 `IF(B{r}="","",...)`으로 비워진다. 이는 기존 설계와 동일.

**중복 표시 방지**: 불변 조건(기간 중첩 없음)으로 고경민은 선택월당 최대 한 행만 활성 상태가 된다.

**직원 마스터 행 확장**: 현재 20행까지 매핑 여유를 두고 생성. 신규 급여 구간 추가 시 마스터에 행을 덧붙이면 급여 요약에도 자동 반영.

### 하단 합계 행

기존 로직 유지. 마지막 직원 행 + 2행에 `SUM(E4:E23)` / `SUM(F4:F23)` / `SUM(G4:G23)`. 빈 행은 공란이라 합산에 포함되지 않음.

## 범위 외

- 기간 중첩 입력 감지 (사용자가 잘못 입력하면 결과 오류 — 비고/주석으로만 안내)
- xlsb 원본 파일 수정
- 실제 지급액(xlsb lump payment)과 근무기록 합산의 불일치 보정 (예: 2025-06 고경민 일급 합 888,000 vs 실제 지급 600,000)
- 기간 전환이 월 중간에 일어나는 경우 (모든 전환은 월 단위 경계에서만 발생한다고 가정)
